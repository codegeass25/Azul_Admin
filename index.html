Booking rules

Reservation fee & payment methods

The reservation fee is required for every new reservation. Existing bookings keep the fee that applied when they were created.

Card, CVV and PIN details are never collected or stored. Online payments now use PayMongo Hosted Checkout and successful payments are verified automatically by the backend webhook. Manual GCash/Maya/other payments still use receipt upload, OCR and admin review.

PayMongo Online Payments

Leave blank to let PayMongo present the payment methods enabled for your merchant account.

PayMongo secret keys and webhook secret stay in the backend .env and are never returned by the admin UI.

Event payment channels (tournaments & Open Play)

Account details and QR codes are shown to clients when they pay a registration or entrance fee. Gateway secrets never leave this server.

Card payments always use the PCI-compliant hosted checkout. If no checkout URL is configured, clients see Card as unavailable. Card numbers, CVV and PINs are never collected or stored.

Email (SMTP)

Credentials stay on the backend PC and are never sent to the browser.

SMS (SMS Gateway Cloud)

Text messages are sent by the Android phone running SMS Gateway, using its own SIM and mobile promo. The gateway endpoint and credentials live in the backend .env file only — they are never sent to this page. If SMS fails, bookings still succeed.

Security & backup

Database backup

Operational controls for the facility administrator. This section contains only administrator password management, database backup, and system reset. To restore: stop the server, replace database.sqlite3 with the backup, then start the server again.

Reset system data

Permanently removes client/player records, bookings, payments, transactions, tournament and Open Play records, registrations, OCR/receipt history, notification history, audit logs, webhook history, and uploaded payment receipts. Settings, facility configuration, admin accounts, courts and court time-slots are preserved.
